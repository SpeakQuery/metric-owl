Metric Owl is in active development. This page separates the working preview from the features still on the way.

In the current preview

  • English web control center with dark and light themes.
  • Live CPU, memory, network, disk and process measurements.
  • Local SQLite history with progressive summaries and event evidence.
  • Ready-made rule packs, editable thresholds and time windows.
  • Installer-created administrator credentials and optional two-factor authentication with a local QR code; keyed setup remains available for manual installs.
  • Public-IP HTTPS browser access configured by the guided installer, with private local/SSH access retained.
  • Local and SSH stdio MCP access with separate, revocable client keys.
  • Six named AI providers with automatic model/endpoint settings and an in-panel connection test.
  • Server AI: short English/Turkish text chat grounded in this host’s monitoring evidence, using your own provider key.
  • Ten read-only MCP tools for current readings, covered history, period reports, process snapshots, configured checks, collection health and incident evidence.
  • Branded HTML and plain-text warning, critical, recovery and scheduled-summary emails, with recipient verification and optional SMTP/relay delivery.
  • Signed webhooks and optional email connection screens.
  • Local root-only account recovery and explicit clean-removal options, documented with safeguards.

Server AI and deeper evidence · v0.1.0-preview.10

The current preview adds Server AI chat directly in the control center. Choose Grok, OpenAI, Claude, Gemini, DeepSeek or Mistral, paste your API key and connect. Model and endpoint settings are handled automatically. Chat stays focused on the single monitored server and answers in the language of an English or Turkish question, usually in 2–5 sentences. Manual chat permits 20 provider attempts per UTC day; optional automatic incident explanations retain their separate 10/day budget. Provider fees apply.

MCP now has ten independently scoped read tools. Period reports include weighted means, differences, peak intervals, coverage and integrity limits; historical process snapshots are collected prospectively and retained for seven days. Configured monitor states and collection health are explicit. Missing data is not treated as zero, unconfigured sources are not called healthy, and correlation does not establish cause. Existing client permissions must be deliberately updated; keys are not silently broadened.

The administrator remains signed in for the browser session without repeated five-minute verification. Initial authentication, CSRF protection, logout and session invalidation remain in place. Root-only account recovery and a deliberate database purge are described in the operations guide; they are not public web actions.

The version-pinned GitHub release contains the application, bundled panel, installer helpers, checksums and source provenance. A passing source test does not establish a fresh installation on every listed OS. The platform evidence below preserves its original scope.

Platform validation

The same installer locally detects Ubuntu 22.04 / 24.04 / 26.04 LTS or Debian 12 / 13 on x86-64. Detection does not upload a machine inventory. ARM64 and Windows server binaries are not published.

  • Ubuntu 24.04: the exact anonymous GitHub command for v0.1.0-preview.5 passed a fresh installation on a real server. The service started, a trusted IP certificate was issued on port 8443, and a username/password account was created without a domain, setup key or required MFA. External HTTPS browser sign-in, live data and chart rendering passed. A certificate-renewal dry run against Let’s Encrypt staging also succeeded; existing hosted-site configuration, certificates and checked routes were preserved.
  • Ubuntu 22.04 / 26.04 and Debian 12 / 13: the static musl binary passed fresh-account creation, password sign-in, SQLite and real-metric reads with email disabled in isolated userspaces sharing an Ubuntu 24.04 kernel. These are not full OS, systemd, firewall or certificate-installation tests.
  • Apple Silicon macOS: local development/application checks only; no public installer package.

What we’ve exercised

The application has run on Apple Silicon macOS and Ubuntu 24.04 x86-64. Local tests cover authentication, rule boundaries, history aggregation and an actual SSH MCP connection to an Ubuntu test instance. These checks do not establish every target platform or long-term production workload as supported.

The screenshots on this website show the actual application interface with synthetic, non-sensitive example data. They are not a public connection to an owner’s machine.

The distributed Ubuntu uninstaller passed while preserving the test account and history. A second fresh GitHub installation selected port 9443 when 8443 was occupied; trusted HTTPS, password sign-in, live CPU and SSE passed, and the existing 8443 listener remained untouched.

Fresh SSH MCP checks passed for server information, current readings and aligned CPU/RAM history; restricted scopes and revoked access were rejected, with no AI requests made.

Additional preview checks

  • Restart notifications after a server comes back online.
  • TLS certificate expiry checks and richer HTTP checks.
  • Scheduled-job and backup completion monitoring.
  • More Linux pressure, disk I/O and capacity signals.
  • Readable hosted-domain and service discovery.

These checks are implemented in the public preview and are undergoing release acceptance. No public production release is implied.

Later, with Pro

A central fleet dashboard, independent full-host outage monitoring and team workflows are planned for a separate Pro repository. Pro is not available yet. You can already run independent free-edition installations on multiple servers.

Clearer monitoring at a glance · v0.1.0-preview.9

Overview now opens first, bringing live measurements together with a compact table of your saved CPU, memory and disk rules. Thresholds, time windows and enabled states reflect your configuration. Setup guidance and connections are optional; rule packs remain available below the saved-rule table.

Focused browser checks cover saved and disabled rules, missing or empty rule data, opening the custom-rule editor without changing existing alarms, and desktop/mobile layouts in both themes. Existing local-agent browser regressions also passed. This is UI validation, separate from the versioned server-installation checks above. Email connection status does not prove inbox delivery.

Open-source free edition · v0.1.0-preview.8

The free edition is now licensed under Apache License 2.0. Each installation monitors its own host; there is no license server-count limit on independent installations. Third-party components and media retain their own licenses. Earlier release tags and assets remain unchanged.

Password setup update · v0.1.0-preview.7

Administrator passwords now require at least 8 characters, with no uppercase, number or symbol requirement. Short or mismatched passwords are requested again in the same installer session. This release rebuilds the application and bundled panel with the updated policy.

Included from preview.6

Fixes CloudPanel configuration discovery, asks for administrator credentials first, and automatically uses an unambiguous public IP. Installer regression tests are separate from full customer CloudPanel installation validation, which remains pending.

The source and Ubuntu / Debian x86-64 release are available on GitHub. The GitHub installer prepares HTTPS access on your own public IPv4 address at an available panel port (8443 by default); no domain or central account is required. Optional two-factor authentication uses a QR code generated locally in your browser.

Optional AI provider fees are paid by the user. Email can use your own SMTP provider; a central notification relay is optional and provider charges may apply. Direct SMTP inbox delivery has not been tested for this preview.
